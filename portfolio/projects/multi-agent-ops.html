The problem

On a construction-tech SaaS, every budget scenario needs each schedule activity linked to the budget items it consumes, and each item's cost split across those activities. Engineers did it by hand: about a month per cycle, and every cost report downstream depended on it.

How it works

  1. LoadPulls the schedule and the budget tree through the platform API, acting with the user's own token.
  2. MatchThe LLM proposes activity → budget-item matches in batches, guided by a reference project when there is one.
  3. ReviewA LangGraph interrupt: the user approves, edits or asks for a recalculation. Nothing is saved yet.
  4. Split costsDeterministic code splits each item's cost across its activities, and the user reviews again.
  5. SaveApproved results are written back through the platform API.

Deterministic codeAI modelHuman decision

Key decisions

  • The LLM only does what needs judgment. Parsing, cost math and writes are plain, deterministic code.
  • An accuracy harness with real projects as fixtures measures recall, leakage and misses over 3 runs per case, compared against a blessed baseline per model and commit.
  • Human-in-the-loop by design: interrupts with Redis checkpoints, so a session resumes exactly where it stopped.
