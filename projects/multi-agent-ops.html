Budget-Matching Agent

Production · Confidential

LangGraph agent that matches schedule activities to budget items and splits costs, cutting each cycle from ~1 month to ~40 minutes (~99%) for a construction-tech SaaS platform.

Problem

On a construction-tech SaaS, every budget scenario needs each schedule activity linked to the budget items it consumes, and each item's cost split across those activities. Engineers did it by hand: about a month per cycle.

Architecture

LangGraph graph with two human-approval interrupts: the LLM proposes activity-to-budget-item matches in batches (guided by a reference project when available), the user approves or edits, deterministic code splits costs, the user reviews again, and approved results are written through the platform API. Sessions persist in TTL-bounded Redis checkpoints; bearer-token pass-through keeps credentials out of the agent.

Tech Stack

  • LangGraph
  • LangSmith
  • Claude
  • pgvector
  • Redis
  • FastAPI
  • React 19
  • TypeScript
  • AWS (ECR, S3)
  • Kubernetes + Argo CD

LangGraph + LangSmith for orchestration and tracing, PostgreSQL + pgvector for retrieval, Redis for checkpointing. Anthropic and OpenAI models sit behind a provider abstraction so the LLM is swappable. Backend: FastAPI + async SQLAlchemy + PostgreSQL. Frontend: React 19 + TypeScript + Tailwind + Server-Sent Events.

Engineering Highlights

  • The LLM only does what needs judgment; parsing, cost math and writes are deterministic code.
  • Accuracy harness: real projects as fixtures, recall / leakage / misses over repeated runs per case, compared against a blessed baseline per model and commit (hardest case: recall 0.17 -> 1.00, zero leakage).
  • Human-in-the-loop by design: LangGraph interrupts with Redis checkpoints, resumable exactly where the session stopped.

Outcomes

  • ~99% cycle-time reduction (~1 month -> ~40 minutes per budget cycle).
  • Production system on the client's platform; client under NDA.
